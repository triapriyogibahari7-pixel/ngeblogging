# Customer SaaS integration staging — not ready for production activation

The production-entry source wrapper cloudflare/domain-recovery-worker-v2.mjs now imports the customer gateway factory, binds it to the existing handleDomainRequest handler and dispatches /api/domains/connect-existing before legacy routes. The factory returns null for unrelated paths. Existing pending recheck, reconciliation, recovery and scheduler dispatch remain in place. This describes source in the SaaS branch, not a verified live deployment.

The customer form/instructions are not switched yet. Existing-file UI edits and optional custom_metadata handling in the legacy SaaS registration payload from the prepared patch remain pending. Do not merge as a completed end-to-end BYOD feature. The old registration/paid route is not removed or globally converted to SaaS.

BYOD uses independent CUSTOM_DOMAIN_BYOD_ENABLED and CUSTOM_DOMAIN_BYOD_SAAS_READY flags, default disabled. The gateway forces legacy SaaS flags only on a derived request environment, after platform/manager/provider preflight, without altering global full-zone/paid configuration. No flags or secrets are configured by these commits.

Fifteen mocked contract/router tests passed in reconstructed approved-file copies on Node v20.20.1. Six production-wrapper dispatch tests with stubbed imports passed on Node v20.20.1. These are not full real-module integration, the repository Node 22.12.0 target, native Workers, a full UI build, GitHub CI or deployment acceptance. Re-run all source tests after integration and review actual legacy registration behavior.

Before activation: verify platform SaaS provisioning, exact zone/account, active fallback origin, proxied routing target, credentials, custom metadata capability, database authorization and provider-state persistence. This is not a replacement of the legacy backend, durable global provisioning queue or atomic ownership cutover. Unknown registration outcomes may finish after timeout; inspect state before retrying.
