# Planning installation after paid registration

This is a pure internal validator of trusted backend records. It does not read the database, authenticate a caller, reserve a domain, create a site-domain row, create a zone, change nameservers/DNS, attach Worker routing, dispatch work or mark installation active. It is not wired into the runtime in this commit. Never accept its evidence object from a browser as authorization.

Planning requires matching production order, persisted verified Midtrans event, confirmed registration ledger/reference, quote amount/provider/domain, immutable destination binding, and current site owner. Missing evidence, refunded/unpaid orders, transferred/deleted sites, review reasons and conflicting domain mappings are blocked. A same-site mapping may only be planned for reconciliation, not presumed active. The supported domain shape remains the existing two-label registration scope; this does not add compound-extension support.

An eligible plan is not authority to mutate. A future backend reader must obtain these records using trusted access. Multi-request reads are not an atomic snapshot. A future dispatcher must revalidate under a durable order/domain claim, prevent conflicting installations, verify the Cloudflare zone account and separate domain/Workers token permissions, then reconcile DNS, HTTPS and routing evidence. Registration token availability alone does not establish those permissions. Never overwrite a mapping on another site or select a substitute site if ownership changes.

Fifteen candidate validator tests passed locally on Node v20.20.1 with synthetic records and network disabled. They are not PostgreSQL, reader/dispatcher integration, React tests, supported Node >=22.12.0 build validation or live provider verification. installationStarted, installationConfirmed and purchaseAllowed stay false even on an eligible plan. No migration, activation, deployment, paid runner, payment or domain purchase is part of this commit.
