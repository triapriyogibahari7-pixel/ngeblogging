# Transactional migration implementation - untested, unapplied

Adds a service-role-only transactional RPC, per-site exclusive persistent locking, versioned immutable-snapshot journal writes, full record snapshot compare-and-set, provider-field commit/rollback, and maintenance triggers on domain and selected site writes. Apply after the journal foundation SQL only after staging review. No SQL is executed by this patch. Locks have no automatic expiry. The JS database adapter is per execution/request and never a shared singleton.

The production Worker source now dispatches POST /api/domains/migrations to the authenticated runtime. Status authenticates against Supabase and reauthorizes site owner/admin through the RPC. No journal snapshots or fences are returned to the browser. Missing schema/secrets fail closed. This is SOURCE wiring, not deployment or verified availability.

Prepare/cutover/rollback deliberately return MIGRATION_PROVIDER_ADAPTER_NOT_READY. The concrete Cloudflare provider adapter, durable provider-operation RPC/checkpoints, authoritative DNS and route-bound content/TLS proofs, verified source restoration and per-alias refresh integration are NOT finished. Do not call this a complete migration service. The SQL rollback trusts a server executor's source proof; it does not independently observe DNS/TLS. Source proof and target receipt invariants still need additional database-side validation and negative tests before activation.

Database triggers prevent writes during a held lock but cannot cancel provider API calls already launched by legacy handlers or cron. Those writers still need a shared maintenance acquisition protocol BEFORE any external mutation, plus draining and reconciliation of in-flight work. No activation flag bypass is provided. Alias metadata is preserved with exact staged host bindings added under ownership_verification.saas_migration; existing refresh code still needs to consume that map correctly before activation.

No SQL syntax execution, transaction/concurrency tests, full build, native Worker tests or live provider checks have been run. Before applying SQL: verify trigger interaction, RLS/grants, recovery of crashed acquisition, role revocation during operations, concurrent old writers, source-proof checks, snapshot conflicts, lost responses and rollback compensation. An uncertain RPC/provider outcome must retain/reconcile the lock; do not blindly retry mutating calls. No deployment, DNS edits or customer migrations are authorized by committing these files.
